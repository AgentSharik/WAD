# Протокол прогона в виртуальной машине

Внутренний документ. Составлен 2026-09-11 под версию 0.4 (`9e31d64`).
Прогон выполняет автор: в песочнице Windows нет, всё, что ниже, здесь проверить нельзя.

**Правило:** релиз без прогона не выпускается. Прогон идёт по снимку (snapshot) — так
повторный запуск занимает минуты, а не час.

---

## Что подготовить

1. **Снимок ВМ** до запуска. Имя: `перед-0.4-Clean` / `перед-0.4-Custom`.
2. **Объём ОЗУ.** Ветка файла подкачки зависит от памяти: для проверки отключения нужно
   выделить ВМ **32 ГБ и больше**, для проверки автоматического режима — меньше 32 ГБ.
   Одним прогоном проверяется только одна ветка.
3. **Разрядность и сборка Windows** записать в отчёт: поведение реестра и списка приложений
   отличается между 10 и 11.
4. **Учётная запись.** Скрипты запускаются из профиля администратора, логи падают в его
   `Documents` (в Custom-режиме — профиль, созданный установщиком).

## Куда смотреть после прогона

Модули пишут логи сами (шесть файлов, имена точные):

| Лог | Кто пишет | Режим |
|---|---|---|
| `Initial_Setup.log` | `initial-setup.ps1` | только Clean |
| `System_Optimization.log` | `clean-and-photo.ps1` | оба |
| `System_Components_Install.log` | `install-sys-components.ps1` | оба |
| `software-install.log` | `apps-install.ps1` | оба |
| `office2024-install.log` | `office-install.ps1` | оба |
| `windows-clean-scripts.log` | `reset-setup-scripts.ps1` | оба |

**У менеджера своего лога нет** (известный дефект Е.2) — его статусы фиксируются только
скриншотом окна. Это не отговорка, а причина его чинить в v2.

Каждый модуль перед закрытием лога печатает строку `ИТОГ: замечаний — N` и список проблем.
**Если в логе «замечаний нет», а по факту ничего не установилось — это дефект, записать.**

## Прогон А. Режим Custom (установка с нуля)

Файл ответов и установочный образ — как обычно, из корня репозитория.

| № | Что проверяем | Ожидаемый результат |
|---|---|---|
| А1 | Установка идёт без вопросов | Ни одного ручного шага, кроме разметки диска (она намеренно ручная) |
| А2 | Скрипты доехали | `C:\Windows\Setup\Scripts` содержит `manager.ps1` и модули |
| А3 | Кодировка после перезаписи | Русский текст в файлах читается, командная строка не показывает кракозябр |
| А4 | Менеджер открылся | Окно само, четыре задачи в списке |
| А5 | Задачи прошли | Все четыре «✓ Готово», исключений в логах нет |
| А6 | Просмотр фото | Двойной щелчок по `.jpg` открывает классический просмотрщик, а не «Фотографии» |
| А7 | Файл подкачки | ОЗУ < 32 ГБ — автоматический; ≥ 32 ГБ — отключён после перезагрузки |
| А8 | Кнопка GitHub | Открывает `github.com/AgentSharik/WAD` (раньше вела на чужой репозиторий) |
| А9 | Финальная зачистка | Папка `C:\Windows\Setup\Scripts` удалена — так и задумано |

## Прогон Б. Режим Clean (уже установленная Windows)

Ссылка для людей: `https://github.com/AgentSharik/WAD/raw/main/loader.ps1` (проверена:
302 → 200, отдаётся как `text/plain`).

| № | Что проверяем | Ожидаемый результат |
|---|---|---|
| Б1 | Запуск | Окно «ЗАГРУЗЧИК АВТОМАТИЧЕСКОЙ НАСТРОЙКИ», запрос прав администратора |
| Б2 | Проверка интернета | При живом интернете идёт дальше |
| Б3 | Скачивание и распаковка | Архив скачан, скрипты в `C:\Windows\Setup\Scripts` |
| Б4 | Перезапись в UTF-8 с BOM | Русский текст читается |
| Б5 | Менеджер | Открылся, **пять** задач (в Custom их четыре) |
| Б6 | Все пять задач | «✓ Готово», логи без исключений |
| Б7 | OneDrive | Удалён: нет в трее, нет пункта в проводнике, задачи обновления нет |
| Б8 | Просмотр фото | **Как А6** — это то, что перенесено из Custom 25.07 в этой версии и раньше в Clean не работало |
| Б9 | Файл подкачки | **Как А7** |

## Прогон В. Негативный — проверка честности статусов (главное в 0.4)

| № | Что делаем | Ожидаемый результат |
|---|---|---|
| В1 | Отключить сеть **перед** задачей «Установка софта» | Задача становится «✗ Сбой (Код: 1)», не «✓ Готово» |
| В2 | Открыть `software-install.log` | Строка `ИТОГ: замечаний — N` со списком: по каждой программе причина |
| В3 | Вернуть сеть, запустить задачу повторно | Задача проходит зелёной |
| В4 | Запустить один модуль вручную и посмотреть код возврата | `$LASTEXITCODE` = 1 при замечаниях, 0 при чистом проходе |

**Ожидаемо сломано, не удивляйтесь:** ветка «нет интернета» в загрузчике советует запустить
`Loader.cmd`, которого никто не создаёт (дефект Е.4). Если в режиме Clean на машине без сети
окно просто закрывается — это дефект Е.11, известен.

| Прогон | Windows (сборка) | ОЗУ | Итог | Что пошло не так | Логи и скриншоты |
|---|---|---|---|---|---|
| А | | | | | |
| Б | | | | | |
| В | | | | | |

Что приложить: **все** `*.log` из `Documents` (даже если «всё прошло»), скриншот окна менеджера
со статусами, скриншот ошибки — если была.

## Чего этот прогон не проверяет

- Поведение на OEM-образах (там `C:\Windows\Setup\Scripts` может содержать чужое — дефект Е.8).
- Срабатывание таска `PauseWindowsUpdate` в режиме Custom (дефект Е.10) — смотреть отдельно
  в планировщике после первого входа.
- Повторный запуск после выключения на середине (продолжение с места) — появится в v2.
