# Changelog

> Нумерация версий и этот файл введены при оформлении репозитория (сентябрь 2026).
> Записи до 0.3 восстановлены по истории коммитов Git: до этого версии не помечались тегами,
> а сообщения коммитов технические («Add files via upload», «Update …»). Поэтому состав версий
> описан по фактическим изменениям файлов, а не по сообщениям.

## 0.4 — честные статусы задач, перенос улучшений между режимами, проверки на каждый push

> Репозиторий переименован: `powershell-scripts` → **`WAD`** (11 сентября 2026).
> Старые адреса GitHub отдаёт редиректом, включая архив `archive/refs/heads/main.zip`,
> поэтому уже распространённые копии загрузчика продолжают работать.

### ✨ Новое

1. **Проверки на каждый push** (GitHub Actions, `windows-latest`): разбор синтаксиса под Windows
   PowerShell 5.1, сверка копий между режимами, контроль кодировки UTF-8 с BOM, статический анализ
   PSScriptAnalyzer (уровень «ошибка»). Логика проверок — в `tools/check.ps1`, тот же файл можно
   запустить у себя перед отправкой правок.
2. **Сверка копий между режимами.** Четыре общих файла (`apps-install.ps1`, `install-sys-components.ps1`,
   `office-install.ps1`, `reset-setup-scripts.ps1`) обязаны совпадать байт-в-байт в обеих папках.
   Расхождение теперь валит проверку: раньше копии разъезжались молча.
3. **Итог этапа в логе.** Каждый модуль печатает перед закрытием лога строку «ИТОГ: замечаний …»
   со списком проблем или «ИТОГ: замечаний нет».

### 🐞 Исправлено

1. **Главное: сбой больше не выглядит как «✓ Готово».** Модули глушили ошибки в предупреждения
   и завершались с кодом 0, а менеджер красит задачу по коду возврата. Теперь в этих скриптах
   предупреждение означает замечание: этап печатает список проблем и отдаёт код 1 — задача краснеет.
   Заодно проверка «не запущено от администратора» отдавала код 0 (`Exit` без числа) — теперь 1.
2. **Режим Clean получил то, что раньше было только в Custom** (перенесено из версии от 25 июля):
   ассоциации фото через `DefaultAppAssociations.xml` и `dism /Import-DefaultAppAssociations`,
   вторая ветка файла подкачки (32 ГБ и больше — отключение), расширения `.jfif` и `.wdp`.
   До этого в Clean просмотрщик фотографий только появлялся в списке «Открыть с помощью».
3. **`Scripts for Custom Windows (with Autounattend)/clean-and-photo.ps1` не разбирался
   Windows PowerShell 5.1** — файл лежал без BOM, кириллица читалась как мусор и ломала строку.
   На домашнем ПК без PowerShell 7 скрипт просто не выполнился бы. Нашла проверка в CI.
4. **Кнопка «GITHUB РАЗРАБОТЧИКА» в режиме Custom** вела на чужой репозиторий
   (`alexejnekrasov/powershell-scripts`) — теперь на свой.

### 🧪 Тесты

- Разбор синтаксиса и PSScriptAnalyzer (уровень «ошибка») — чисто; копии сверены; проба механизма
  итогов: предупреждение → код 1 и список проблем, чистая работа → код 0.
- На живой Windows по-прежнему не проверялось: установка по файлу ответов, интерфейс, реестр,
  файл подкачки, ассоциации, таски планировщика. Это проверяется прогоном в виртуальной машине.

## 0.3 — просмотр фото через DISM, вторая ветка файла подкачки, чистые логи

### ✨ Новое

1. **Классический просмотр фотографий настраивается по-настоящему.** Скрипт формирует файл ассоциаций
   (`DefaultAppAssociations.xml`) и применяет его через `dism /Online /Import-DefaultAppAssociations`.
   Раньше запись шла только в ветку `Photo Viewer\Capabilities\FileAssociations` — приложение появлялось
   в списке «Открыть с помощью», но по умолчанию не становилось.
2. **Файл подкачки: появилась вторая ветка.** Если ОЗУ 32 ГБ и больше, автоматическое управление отключается
   и существующие файлы подкачки удаляются; если меньше 32 ГБ — включается автоматический размер.
   До этого при большом объёме памяти скрипт просто ничего не делал.
3. **Строгая проверка кода возврата DISM.** Ненулевой код теперь приводит к ошибке этапа, а не к тихому
   продолжению работы.

### 🐞 Исправлено

1. **Убраны `-ForegroundColor` из сообщений** — при записи через `Start-Transcript` управляющие
   последовательности попадали в лог-файл и мешали его читать.
2. **Добавлена заключительная строка этапа очистки** («Очистка UWP-приложений завершена») — теперь
   по логу видно, что этап дошёл до конца, а не оборвался.
3. **Шапка файла приведена к его имени** (`clean-and-photo.ps1` вместо старого `clean-optimization-full.ps1`).

## 0.2 — два режима: Clean и Custom

### ✨ Новое

1. **Разделение на два сценария установки.** Появились `Scripts for Clean Windows` (для уже установленной
   ОС, запуск через `loader.ps1`) и `Scripts for Custom Windows (with Autounattend)` (для установки с нуля,
   запуск из файла ответов). Замысел: один и тот же результат двумя путями.
2. **`initial-setup.ps1` — пятая задача для чистой Windows.** Воспроизводит то, что в режиме Custom делает
   файл ответов: настройки Edge, панели задач, меню «Пуск», телеметрии и профиля пользователя по умолчанию.
3. **`manager.ps1` для режима Custom** — четыре задачи (без `initial-setup.ps1`) и обновлённый
   `autounattend.xml`, который подтягивает скрипты из новой папки.
4. **Урезанный список удаляемых приложений в режиме Custom** (18 пакетов против 33 в Clean): приложения
   из разницы уже удалил файл ответов на этапе установки.

### 🐞 Исправлено

1. **Старый каталог `Scripts/` удалён** — вместо него два режимных каталога, структура стала однозначной.

## 0.1 — первая рабочая версия

### ✨ Новое

1. **`loader.ps1`** (сначала `Загрузчик.ps1`) — единый файл запуска для уже установленной Windows:
   сам запрашивает права администратора, проверяет интернет, скачивает актуальные скрипты в
   `C:\Windows\Setup\Scripts` и запускает менеджер. Позже переименован в `loader.ps1`.
2. **Менеджер с собственным интерфейсом** — безрамочное окно, свой заголовок, список задач со статусами,
   анимированный прогресс с градиентным бликом, диалог завершения. Разработан за несколько итераций
   (первая версия — 14 КБ, после переработки 8 июля — 21 КБ).
3. **Модули пост-установки:** `clean-and-photo.ps1` (очистка системы, OneDrive, файл подкачки),
   `install-sys-components.ps1` (библиотеки), `apps-install.ps1` (базовый софт), `office-install.ps1`,
   `reset-setup-scripts.ps1` (финальная зачистка).
4. **`autounattend.xml` в корне репозитория** — файл ответов для установки с нуля; разметка диска
   намеренно оставлена ручной.
5. **README** с описанием обоих способов запуска и скриншотом интерфейса.

### 🐞 Исправлено

1. **Несколько итераций по `apps-install.ps1`** в первые два дня — загрузка установщиков приведена
   к повторным попыткам и отбраковке повреждённых файлов.
